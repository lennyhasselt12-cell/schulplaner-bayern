SCHULPLANER – Supabase-Verbindung

Diese Version enthält E-Mail-/Passwort-Anmeldung und speichert den kompletten Planer-Datensatz pro Benutzer in public.user_settings.settings (JSONB). Die Projekt-URL und der Publishable Key sind bereits in script.js eingetragen. Die Tabellen subjects, teachers und timetable_entries bleiben in dieser Version ungenutzt.

WICHTIG ZUR DATENTRENNUNG
- Beim Login wird ausschließlich der Datensatz mit der eigenen user_id geladen.
- RLS muss für public.user_settings aktiviert sein.
- Die SELECT-/INSERT-/UPDATE-Policies müssen authenticated Benutzer auf auth.uid() = user_id beschränken.
- Die vorhandene Policy „Users manage own settings“ (FOR ALL) ist dafür geeignet, sofern USING und WITH CHECK jeweils auth.uid() = user_id verwenden.
- Beim ersten Login auf einem Gerät können vorhandene Gastdaten übernommen werden.
- Sobald auf dem Gerät bereits ein anderes Konto angemeldet war, wird für ein neues Konto ohne Cloud-Datensatz ein leerer eigener Datensatz angelegt. So werden lokale Daten nicht versehentlich zwischen Konten geteilt.

DATENVERHALTEN
- Ohne Anmeldung bleiben Daten lokal im Browser.
- Beim ersten Login werden lokale Gastdaten einmalig übernommen, sofern auf diesem Gerät noch kein anderes Konto als aktiver Nutzer gespeichert war.
- Bei späteren Logins werden vorhandene Cloud-Daten geladen und lokale Daten damit ersetzt.
- Änderungen werden lokal und nach kurzer Verzögerung online gespeichert.
- Dasselbe Konto kann auf mehreren Geräten verwendet werden. Die Geräte laden denselben Cloud-Datensatz.
- Unterschiedliche Konten erhalten getrennte Datensätze. Die tatsächliche Sicherheit hängt zusätzlich von korrekt aktivierten RLS-Policies ab.

DATEIEN
Die ZIP enthält index.html, style.css, script.js und diese Anleitung. Alle vier Dateien können im GitHub-Repository ersetzt werden.

SICHERHEIT
Nur den Publishable Key im Frontend verwenden. Niemals den Supabase Secret Key oder Service-Role-Key veröffentlichen.

TEST
Nach dem Commit: Konto A anmelden, Testfach und Teststunde anlegen, abmelden, Konto B anmelden und prüfen, dass A-Daten nicht erscheinen. Anschließend Konto A auf einem zweiten Gerät anmelden und die Synchronisierung in beide Richtungen prüfen. Erst danach echte Daten verwenden.
